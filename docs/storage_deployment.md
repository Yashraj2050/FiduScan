# FiduScan — Cloudflare R2 Storage Deployment

**Version:** v9.0-timesformer-video  
**Last Updated:** 2026-06-11

---

## Storage Architecture

FiduScan uses Cloudflare R2 as its object storage layer for:
- User-uploaded evidence (images, audio, video)
- Forensically watermarked media generated by the system
- PDF and JSON case reports

R2 is fully S3-compatible, allowing us to use the standard `boto3` AWS SDK. The storage service now supports **presigned POST URLs**, which means large files (up to 500MB) can be uploaded directly from the frontend browser to R2 without passing through and bottlenecking the Railway backend.

---

## Deployment Readiness

- **S3 Client Configuration:** Updated to force `signature_version='s3v4'` (required by Cloudflare R2).
- **Startup Safety:** Refactored to use lazy initialization. The backend will no longer crash at startup if R2 credentials are missing; errors are deferred until an upload/download is actually attempted.
- **Dependency Fallback:** `python-magic` is used for deep MIME validation, but it requires the `libmagic` C-library. A graceful fallback to Python's built-in `mimetypes` ensures uploads still work in lean container environments.
- **Dependencies Added:** `boto3` and `boto3-stubs[s3]` have been added to `requirements.txt`.

## Required Environment Variables (4)

Set the following in Railway under Project Variables:

```bash
# Example Endpoint (replace <account-id> with your Cloudflare Account ID)
R2_ENDPOINT_URL=https://<account-id>.r2.cloudflarestorage.com

# R2 API Tokens (Create these in Cloudflare Dashboard -> R2 -> Manage R2 API Tokens)
# Permissions required: "Object Read & Write"
R2_ACCESS_KEY_ID=<your-access-key-id>
R2_SECRET_ACCESS_KEY=<your-secret-access-key>

# Bucket Configuration
R2_BUCKET_NAME=fiduscan-prod
```

## Pre-Deployment Setup (Cloudflare Dashboard)

1. Log into Cloudflare Dashboard.
2. Go to **R2**.
3. Click **Create bucket**. Name it `fiduscan-prod`.
4. Go to **Manage R2 API Tokens** (top right).
5. Click **Create API token**.
6. Set Permissions to **Object Read & Write**.
7. Specify the bucket `fiduscan-prod` or leave as all buckets.
8. Copy the generated Access Key ID and Secret Access Key into Railway.

## Storage Operations

### 1. Direct Backend Upload (`upload_file`)
- Validates file size (Max 500MB).
- Validates MIME type against an allowed list (`image/jpeg`, `video/mp4`, etc.).
- Uses `ExtraArgs={"ContentType": mime}` to ensure the file is served correctly.

### 2. Presigned GET (`generate_presigned_url`)
- Generates a temporary, cryptographically signed URL to allow users to view/download evidence.
- Default expiration: 1 hour (3600 seconds).

### 3. Presigned POST (`generate_presigned_post`)
- Generates a secure payload for the frontend to upload files directly to R2.
- Enforces content-type and size limits at the Cloudflare edge.

### 4. Deletion (`delete_file`)
- Deletes objects. (Future: Implement soft-delete or lifecycle rules for legal hold).
